# 言语行为理论学习笔记

## 1. 理论概述

言语行为理论（Speech Act Theory）起源于 J. L. Austin 的系列讲座《How to Do Things with Words》(1962)，后由 John Searle 系统化发展。该理论的核心洞见是：**说话即做事**——说出一句话本身就是完成了一个行动。

在 Austin 之前，语言哲学主要关注陈述句的真假值。Austin 指出，许多话语无法用真假评判（如"I promise"、"I name this ship"），它们本身就是对世界的一种干预。这一认识彻底改变了语用学的面貌。

## 2. Austin 的三分说

Austin 将任何一句话语分析为**三个同时进行的言语行为**：

### 2.1 三分结构

| 行为 | 定义 | 关键表述 | 关注点 |
|------|------|----------|--------|
| **言内行为 (Locutionary)** | **说出**某句话的行为——产生有意义的话语 | "说了什么" | 话语本身（语音、语法、语义） |
| **言外行为 (Illocutionary)** | **在说**某句话时所实施的行为——话语的功能/力 | "说的时候做了什么" | 说话者的意图/约定俗成的力量 |
| **言后行为 (Perlocutionary)** | **通过说**某句话所产生的结果——对听者的实际影响 | "说了之后造成了什么" | 对听众的实际效果 |

### 2.2 言内行为的三层子行为

Austin 进一步将言内行为分为三个子层次：

1. **发音行为 (Phonetic act)**：发出特定的语音
2. **措辞行为 (Phatic act)**：说出属于某种语言的、符合语法的词句
3. **表意行为 (Rhetic act)**：说出具有明确含义（sense）和指称（reference）的话语

### 2.3 经典示例

**例 1:** "Shoot her!"

| 维度 | 描述 |
|------|------|
| **言内** | 他对我说"Shoot her!"（意为"开枪"，指称"她"） |
| **言外** | 他催促/建议/命令我向她开枪 |
| **言后** | 他说服了我开枪 / 他让我开了枪 |

**例 2:** 警告"前方有地雷"

| 维度 | 描述 |
|------|------|
| **言内** | 说了"前方有地雷"这句话 |
| **言外** | 警告听者（表达关切并建议改道） |
| **言后** | 听者绕道而行 |

### 2.4 适切条件 (Felicity Conditions)

一个言语行为要成功（即"适切"），需满足以下条件：

| 条件类型 | 说明 | 示例（命名） |
|----------|------|-------------|
| **程序条件** | 存在约定俗成的程序 | 有正式的命名仪式 |
| **人员条件** | 执行者具备适当资格 | 必须有命名权的人执行 |
| **执行条件** | 程序必须正确完整地执行 | 说出"I name this ship..." |
| **意图条件** | 执行者必须有真诚的意图 | 真正打算命名 |

**汲取（Uptake）**：听者必须同时识别话语的**含义**和**力量**，言外行为才算适切。若听者听到"我警告你"却未意识到这是警告，则言外行为失败。

### 2.5 Austin 的五类言外行为分类

| 类别 | 功能 | 示例 |
|------|------|------|
| **Verdictives（裁决式）** | 做出裁决或评估 | 宣判、评估、排名 |
| **Exercitives（行使式）** | 行使权力/影响力 | 命令、任命、警告、建议 |
| **Commissives（承诺式）** | 承诺未来行动 | 承诺、发誓、打赌 |
| **Behabitives（表态式）** | 对他人的行为或处境做出反应 | 道歉、感谢、祝贺 |
| **Expositives（阐释式）** | 阐明话语在论证中的角色 | 陈述、否认、同意、报告 |

## 3. Searle 的五分类体系

Searle (1975) 在 Austin 的基础上提出了影响更广泛的分类体系，基于三个关键维度：**言外目的（Illocutionary Point）**、**适切方向（Direction of Fit）**、**表达的心理状态（Expressed Psychological State）**。

### 3.1 五分类总览

| 类型 | 核心功能 | 适切方向 | 心理状态 | 示例动词 |
|------|----------|----------|----------|----------|
| **Assertives（断言式）** | 承诺说话者相信命题为真 | 词语→世界 | 信念 | 陈述、声称、报告、断言 |
| **Directives（指令式）** | 让听者去做某事 | 世界→词语 | 愿望/想要 | 命令、请求、建议 |
| **Commissives（承诺式）** | 承诺说话者未来采取行动 | 世界→词语 | 意图 | 承诺、发誓、提供 |
| **Expressives（表达式）** | 表达心理状态/情感态度 | 词语→世界（预设） | 情感（可变） | 感谢、道歉、欢迎 |
| **Declarations（宣告式）** | 说出即改变世界 | 双向 | 无 | 宣判、任命、解雇 |

### 3.2 各类详解

#### 3.2.1 Assertives（断言式）

说话者承诺所表达命题的真实性，描述世界中的事态。

- **适切方向**：词语→世界（词语匹配世界中的信念）
- **心理状态**：信念（说话者相信X）
- **示例**：陈述( stating )、断言( claiming )、假设( hypothesizing )、描述( describing )、报告( reporting )、断言( asserting )、抱怨( complaining )、夸耀( boasting )、预测( predicting )、否认( denying )、承认( admitting )、通知( notifying )
- **典型句**："太阳从东方升起。"——断言了一个事实状态

**对话抗机的意义**：Assertives 构成图谱中的**信息/事实节点**。反方需要检查这些断言是否有关联证据支持。

#### 3.2.2 Directives（指令式）

让听者去做某事，说话者试图让世界符合话语内容。

- **适切方向**：世界→词语（让世界符合词语）
- **心理状态**：愿望/想要（说话者想要X）
- **子类**：问题（Questions）——让听者提供信息
- **示例**：命令( ordering )、请求( requesting )、恳求( begging )、建议( suggesting )、邀请( inviting )、允许( permitting )、挑战( daring )
- **典型句**："我命令你离开。"——指令听者采取行动

**对话抗机的意义**：Directives 构成图谱中的 **Action/需求节点**。这是对抗机**反方**的重点检查对象：
- 悬空 Action 检测：一个 Action（如"做一个菜单"）是否具备必要的上下文（如"结构根节点"）
- 前提条件检查：Action 是否缺少必要的条件/背景

#### 3.2.3 Commissives（承诺式）

承诺说话者未来采取某种行动。

- **适切方向**：世界→词语（让世界符合词语）
- **心理状态**：意图（说话者意图X）
- **示例**：承诺( promising )、发誓( vowing )、威胁( threatening )、提供( offering )、保证( guaranteeing )、签订契约( contracting )
- **典型句**："我保证还你钱。"——承诺了一个未来行动

**对话抗机的意义**：Commissives 节点需要后续跟踪检测是否"兑现"。如果文本后面没有提及该承诺的完成情况，可能是一个信息遗漏。

#### 3.2.4 Expressives（表达式）

表达说话者对某一事态的心理状态、态度或情感。

- **适切方向**：词语→世界（命题真实被预设，无方向）
- **心理状态**：情感（说话者感受到X——愉悦、遗憾、感激、同情等）
- **示例**：祝贺( congratulating )、感谢( thanking )、道歉( apologizing )、哀悼( condoling )、欢迎( welcoming )、原谅( pardoning )、问候( greeting )
- **典型句**："我为我的不良行为道歉。"——表达了对自身行为的态度

**对话抗机的意义**：Expressives 通常携带**情感权重**（正面/负面评价），可用于调整图谱中相关节点的衰减速率或重要度评估。

#### 3.2.5 Declarations（宣告式）

说出即改变世界中的事态，话语本身创造了新的现实。

- **适切方向**：词语→世界**且**世界→词语（话语改变世界，双向）
- **心理状态**：无（不需要特定真诚条件）
- **关键约束**：必须由有相应权威的人在适当的制度框架内执行
- **示例**：宣判( sentencing )、任命( appointing )、解雇( firing )、命名( baptizing )、宣布( declaring war )
- **典型句**："我宣布你们成为夫妻。"——这句话本身改变了二人的法律和社会地位

**对话抗机的意义**：Declarations 在项目典型输入中较少出现（日常口语/写作），但如果出现则代表**高权威节点**，在输出中应给予较高权重。

### 3.3 适切方向的图形理解

```
Assertives:     词语 → 世界    (词语符合世界)
Directives:     世界 → 词语    (让世界符合词语)
Commissives:    世界 → 词语    (让世界符合词语)
Expressives:    世界 ← 词语    (预设世界，无方向)
Declarations:   词语 ↔ 世界    (双向同时改变)
```

## 4. 间接言语行为

### 4.1 定义与问题

**间接言语行为（Indirect Speech Act, ISA）** 是指一句话的字面形式与言外之力不匹配的情况。这是自然语言理解中的核心难题。

**典型例子**："你能把盐递给我吗？"

- **字面形式**：疑问句（关于听者的能力）
- **字面言外之力**：询问（Question）
- **实际言外之力**：请求（Request / Directive）

Searle 区分了**规约性 ISA**（conventionalized，如"Can you..." 已惯用化为请求）和**非规约性 ISA**（non-conventionalized，需要更多语境推理）。

### 4.2 ISA 的分类与识别策略

| ISA 类型 | 描述 | 示例 | 识别难度 |
|----------|------|------|----------|
| **规约性** | 已形成固定的惯用表达 | "Can you...", "Would you mind..." | 低（可建立模式库） |
| **非规约性** | 依赖语境推理 | "It's cold in here." = 请求关窗 | 高（需上下文理解） |

### 4.3 在项目中的处理策略

对于小模型，处理 ISA 的策略：

1. **规约性 ISA 白名单**：在 Prompt 中列出常见中文规约性指令句式：
   - "你能...吗？" → 实际是请求（Directive），不是询问
   - "要不要..." → 实际是建议
   - "不如我们..." → 实际是提议

2. **提示工程约束**：在 Tagger 的 Prompt 中加入：
   ```
   注意：某些句子表面是疑问句或陈述句，实际是请求或指令。
   例如"你能帮我做菜单吗？"字面是问"能不能"，实际是请求做菜单。
   请根据语境判断真正的言语行为类型。
   ```

3. **二次确认机制**：当置信度低于阈值时（对抗机 Phase 6），将 ISA 识别结果推入 AlertBuffer 等待人类确认。

## 5. NLP 应用现状

### 5.1 言语行为识别

| 方法 | 准确率 | 适用场景 |
|------|--------|----------|
| 基于 SVM/RF 的传统方法 | ~79% | 计算资源受限 |
| 基于 BERT 的序列分类 | ~90% | 通用文本 |
| 基于 LLM (GPT-4) + Prompt 工程 | ~82%（复杂文本） | 高质量标注 |
| 混合方法（规则 + ML） | 80-90% | 对话系统 |

### 5.2 主要应用方向

| 应用 | 原理 |
|------|------|
| **RAG 检索增强** | 剥离言外之力标记（疑问词、礼貌语），提取命题内容进行嵌入检索 |
| **对话系统意图识别** | 将言语行为分类作为连接用户话语和系统动作的中间层 |
| **文本摘要** | 区分断言（关键信息）和表达（情感权重），优化摘要内容选择 |
| **Prompt 工程** | 修辞情境理论（exigence/audience/purpose/context）提供结构化 prompt 设计方法 |

### 5.3 相关标准

**ISO 24617-2**：国际标准对话行为标注体系，提供了包含 56 种对话行为的层级分类，可作为扩展参考。

## 6. 本项目映射分析  ★

### 6.1 Searle 五分类到 Chunk Intent 字段的映射

在我们的 Tagger 输出的 Chunk JSON 中，`intent` 字段应直接基于 Searle 五分类：

```python
# Chunk JSON schema 中的 intent 枚举
enum IntentType {
    ASSERTIVE,     # 断言式 — 陈述事实/信息
    DIRECTIVE,     # 指令式 — 要求/请求/命令
    COMMISSIVE,    # 承诺式 — 承诺/保证
    EXPRESSIVE,    # 表达式 — 情感/评价
    DECLARATION,   # 宣告式 — 宣告事实改变
}
```

### 6.2 各类到图谱节点的映射

| Intent 类型 | 图谱节点类型 | 对抗机行为 | 衰减策略 |
|------------|-------------|-----------|---------|
| **ASSERTIVE** | `InformationNode` | 反方检查是否有 Evidence 支持 | 正常衰减 |
| **DIRECTIVE** | `ActionNode` | **反方重点检查**：是否悬空（缺少 Context/前提） | 衰减较慢（需求重要） |
| **COMMISSIVE** | `CommitmentNode` | 反方跟踪：后续是否提及兑现 | 衰减中等 |
| **EXPRESSIVE** | `EvaluationNode` | 调整相关联节点权重 | 快速衰减（即时情感） |
| **DECLARATION** | `StatusChangeNode` | 高权威标记，不质疑 | 几乎不衰减 |

### 6.3 对抗机中的具体检查逻辑（Phase 6 设计参考）

**反方（Prosecutor）** 针对不同类型的检查：

```
if chunk.intent == DIRECTIVE:
    # 检查该 Action 是否有必要的上下文节点
    if missing_context(chunk):
        prosecutor.add_alert("悬空指令", chunk, 
            "这个指令/请求缺乏必要的上下文条件")

if chunk.intent == ASSERTIVE:
    # 检查断言是否有 Evidence 支持
    if no_supporting_evidence(chunk, graph):
        prosecutor.add_alert("无支持的断言", chunk, 
            "这个陈述缺乏证据支持")

if chunk.intent == COMMISSIVE:
    # 注册待跟踪的承诺
    prosecutor.track_commitment(chunk)

if chunk.intent == EXPRESSIVE:
    # 影响相关联节点的置信度
    adjust_confidence_of_related(chunk)
```

**正方（Defender）** 的回应策略：

```
for alert in prosecutor.alerts:
    if alert.type == "悬空指令":
        # 在衰减池中寻找匹配的上下文
        context = defender.scavenge(alert.chunk, relation="BACKGROUND")
        if context:
            defender.resolve(alert, context)  # 找到上下文，解决悬空
        else:
            defender.fail(alert)  # 无法解决，推入 AlertBuffer
```

### 6.4 间接言语行为的处理（补丁）

在 Tagger 的 Prompt 中加入 ISA 检测指令：

```
## 间接言语行为检测
- "你能...?" "可不可以...?" 表面是疑问，实际是【请求/指令】(DIRECTIVE)
- "你要不要...?" 表面是疑问，实际是【建议】(DIRECTIVE)
- "我觉得我们可能需要..." 表面是断言，实际是【建议】(DIRECTIVE)
- "要不..." 表面是选项，实际是【提议】(DIRECTIVE)
```

当小模型无法可靠处理 ISA 时（置信度低于阈值），将结果标记为 `confidence: low` 并推入 AlertBuffer，不强行分类。

### 6.5 与 RST 的协同

言语行为（Intent）和修辞结构（Relation）应视为**正交的标注维度**：

```
Chunk {
    text: "因为时间不够，我们取消了会议。"
    intent: ASSERTIVE,           # 陈述事实
    role: NUCLEUS,               # 核心信息
    relation: NON_VOLITIONAL_CAUSE,  # 因果关系中的结果
    signal_words: ["因为"]
}
```

两者的组合提供了丰富的图谱建边信息：
- `intent: DIRECTIVE` + `relation: CONDITION` = 有条件的需求
- `intent: ASSERTIVE` + `relation: EVIDENCE` = 支持性事实
- `intent: EXPRESSIVE` + `relation: EVALUATION` = 评价性情感
